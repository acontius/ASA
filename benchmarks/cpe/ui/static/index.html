How to annotate a software identity
  1. Inspect the original JSON and identify each software product/version supported by its evidence.
  2. Add one independent identity card for each product/version. A record with three products gets three cards.
  3. Enter only supported product, vendor, version, update, and part values; leave unknown optional values blank.
  4. Copy exact evidence paths from the source record. Decide CPE mapping independently; do not guess a CPE.
  5. Choose the record-level review status, validate, then save. Uncertain records are not confirmed negatives.

Record status applies to the whole record: reviewed = identities are fully annotated; no_software_identity = deliberate reviewed negative; ambiguous = evidence does not resolve identity; insufficient_evidence = not enough evidence; out_of_scope = outside this benchmark.

Synthetic example: if raw evidence contains ExampleServer/2.4 at _source.http.server, add one card for ExampleServer, version 2.4, with that evidence path. This is illustrative only; no fields are prefilled from model output.
